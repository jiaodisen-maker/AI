# PoC 研究备忘录（模板）

> 本文件为法律护栏文档。在 W4 启用 A1 Discovery Agent 的 PoC 通道（MediaCrawler / DrissionPage 抓取抖音、小红书公开 case）之前，必须由法务出具签字版本归档。未归档则 feature flag `POC_CRAWLED_ENABLED` 不得为 true。

---

## 1. 研究目的

本备忘录所授权的网络数据获取行为，**仅限内部研究目的**，用于训练 v6 内容洞察系统的 9 Agent 流水线（A2 Decomposition / A6 Microtype / A8 Generation / A9 Critic + DSPy 自优化）。

**明确不用于**：
- 对外发布脚本或视频内容
- 任何形式的广告投放素材
- 任何商业数据产品的对外销售
- 任何基于第三方平台账号的数据二次售卖

## 2. 数据范围与边界

### 2.1 允许获取
- 抖音 / 小红书等公开平台上**公开可见**的视频 URL 与 metadata
- 视频本体（用于 A2 多模态拆解）
- 视频公开播放数 / 点赞数 / 评论数（聚合统计值，**不含评论文本与用户身份**）

### 2.2 严禁获取
- 评论文本及评论者用户名、UID、头像、个人主页链接
- 视频发布者除其公开账号名外的任何个人信息（手机号、邮箱、地理位置等）
- 任何需要登录态、cookie、滑块绕过、验证码识别才能获取的数据
- 私信、私域社群、未公开的小程序内数据

### 2.3 技术约束
- 使用 MediaCrawler / DrissionPage 必须以"模拟无登录访客"方式运行
- 不得部署任何形式的账号池、IP 轮换池、行为模拟脚本
- 请求频次需符合 robots.txt 与平台公开 ToS
- 全部抓取行为在内部 VPC 沙箱执行，出网代理日志全量留存 ≥1 年

## 3. 数据隔离与销毁

### 3.1 schema 级隔离
- 所有 PoC 通道获取的数据在 `cases` 表中标记 `data_lineage='poc_crawled'`
- 数据库 trigger 强制阻止 `poc_crawled` 数据流入 `generated_scripts` 的对外发布字段
- A8 Generation Agent 引用 `poc_crawled` 数据时强制设置 `for_internal_research_only=true` 标志

### 3.2 销毁机制
- `cases.poc_purge_at = ingested_at + 30 天`
- 后台定时任务到期清理：原始视频文件（MinIO）+ ASR 文本 + OCR 文本 + LLM 中间产物
- 清理后保留：脱敏后的 atoms（content + embedding）+ critic_scores + prompt_versions（用于 DSPy 训练记录）
- 销毁日志归档 ≥3 年

## 4. 上线切换关闸

系统对外发布或投放上线前，**必须执行以下全部步骤**：
1. 设置 feature flag `POC_CRAWLED_ENABLED=false`
2. 执行全量清理脚本：删除所有 `data_lineage='poc_crawled'` 的 cases 及关联 segments / atoms
3. 法务复审签字（本备忘录附件 A）
4. 验证生产 build 中 A1 Discovery Agent 仅保留 OAuth + public_api 通道

未完成上述步骤的 build 严禁部署到生产环境。
