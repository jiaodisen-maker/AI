# 方式 1：Docker 部署 (Docker Compose)

[](<https://github.com/coze-dev/coze-loop/wiki/2.-%E5%BF%AB%E9%80%9F%E5%BC%80%E5%A7%8B#方式-1docker-部署-docker-compose>)

## 准备工作

[](<https://github.com/coze-dev/coze-loop/wiki/2.-%E5%BF%AB%E9%80%9F%E5%BC%80%E5%A7%8B#准备工作>)

请确保您的软硬件环境满足以下要求：

**项目** | **说明**  
---|---  
硬件 | 建议使用 2 核 4G 及以上的硬件配置。  
Go | * 已安装 Go，且版本为 1.24.0 及以上版本。   
* 配置 GOPATH，同时将 `${GOPATH}/bin` 加入到环境变量 PATH 中，保证安装的二进制工具可找到并运行。  
Docker | 提前安装 Docker、Docker Compose，并启动 Docker 服务，详细操作请参考 Docker 文档：   
  
* **macOS** ：推荐使用 Docker Desktop 安装，参考 [Docker Desktop For Mac](<https://docs.docker.com/desktop/setup/install/mac-install/>) 安装指南。   
* **Linux** ：参考 [Docker 安装指南](<https://docs.docker.com/engine/install/>) 和 [Docker Compose](<https://docs.docker.com/compose/install/>) 安装指南。   
* **Windows** ：推荐使用 Docker Desktop 安装，参考 [Docker Desktop For Windows](<https://docs.docker.com/desktop/setup/install/windows-install/>) 安装指南。  
模型 | 已开通 OpenAI 或火山方舟等在线模型服务。目前支持的模型服务列表可参考[模型配置](<https://github.com/coze-dev/coze-loop/wiki/5.-%E6%A8%A1%E5%9E%8B%E9%85%8D%E7%BD%AE>)。  
  
## 安装 Coze Loop

[](<https://github.com/coze-dev/coze-loop/wiki/2.-%E5%BF%AB%E9%80%9F%E5%BC%80%E5%A7%8B#安装-coze-loop>)

### 步骤一：获取源码

[](<https://github.com/coze-dev/coze-loop/wiki/2.-%E5%BF%AB%E9%80%9F%E5%BC%80%E5%A7%8B#步骤一获取源码>)

执行以下命令，获取 Coze Loop 最新版本的源码。
    
    
    # 克隆代码 
    git clone https://github.com/coze-dev/coze-loop.git
    
    # 进入coze-loop目录下
    cd coze-loop

### 步骤二：配置模型

[](<https://github.com/coze-dev/coze-loop/wiki/2.-%E5%BF%AB%E9%80%9F%E5%BC%80%E5%A7%8B#步骤二配置模型>)

正式安装 Coze Loop 开源版之前，你需要准备可选的模型，否则访问 Coze Loop 开源版时将无法选择模型来启动 Prompt 调试或评测。此处以 **OpenAI** 和**火山方舟** 模型为例，演示配置模型文件的操作步骤，你可以快速配置模型以便安装和测试 Coze Loop 开源版。对于 Llama 等其他模型，你可以参考[模型配置](<https://github.com/coze-dev/coze-loop/wiki/5.-%E6%A8%A1%E5%9E%8B%E9%85%8D%E7%BD%AE>)文档填写配置文件。

  1. 编辑文件 `release/deployment/docker-compose/conf/model_config.yaml`，修改 api_key 和 model 字段。以下内容表示为 Coze Loop 开源版配置火山方舟的豆包模型、OpenAI 模型。使用以下内容覆盖原文件，然后修改其中的 api_key 和 model，将其替换为你的 OpenAI 和火山方舟模型的配置参数。

> **`release/deployment/docker-compose/conf/model_config_example/`目录下也给出了Coze Loop支持的市面上主流模型配置示例，可供参考。**
    
    
    models:
      - id: 1
        name: "doubao"
        frame: "eino"
        protocol: "ark"
        protocol_config:
          base_url: ""         # 默认为https://ark.cn-beijing.volces.com/api/v3/，若使用Byteplus ModelArk，请指定为https://ark.ap-southeast.bytepluses.com/api/v3/
          api_key: "*727e****" # 方舟模型 API Key，中国境内用户参考火山方舟文档 https://www.volcengine.com/docs/82379/1541594；非中国境内的用户可参考 BytePlus ModelArk 文档 https://docs.byteplus.com/en/docs/ModelArk/1361424?utm_source=github&utm_medium=readme&utm_campaign=coze_open_source
          model: "ep-****"     # 方舟模型Endpoint ID，中国境内用户参考火山方舟文档 https://www.volcengine.com/docs/82379/1099522；非中国境内的用户可参考 BytePlus ModelArk 文档 https://docs.byteplus.com/en/docs/ModelArk/model_id?utm_source=github&utm_medium=readme&utm_campaign=coze_open_source
        param_config:
          param_schemas:
            - name: "temperature"
              label: "生成随机性"
              desc: "调高温度会使得模型的输出更多样性和创新性，反之，降低温度会使输出内容更加遵循指令要求但减少多样性。建议不要与 “Top p” 同时调整。"
              type: "float"
              min: "0"
              max: "1.0"
              default_val: "0.7"
            - name: "max_tokens"
              label: "最大回复长度"
              desc: "控制模型输出的 Tokens 长度上限。通常 100 Tokens 约等于 150 个中文汉字。"
              type: "int"
              min: "1"
              max: "4096"
              default_val: "2048"
            - name: "top_p"
              label: "Top P"
              desc: "生成时选取累计概率达 top_p 的最小 token 集合，集合外 token 被排除，平衡多样性与合理性。"
              type: "float" #
              min: "0.001"
              max: "1.0"
              default_val: "0.7"
      - id: 2
        name: "openapi"
        frame: "eino"
        protocol: "openai"
        protocol_config:
          api_key: "***"  # OpenAI API Key
          model: "***"    # OpenAI 模型 ID
        param_config:
          param_schemas:
            - name: "temperature"
              label: "生成随机性"
              desc: "调高温度会使得模型的输出更多样性和创新性，反之，降低温度会使输出内容更加遵循指令要求但减少多样性。建议不要与 “Top p” 同时调整。"
              type: "float"
              min: "0"
              max: "1.0"
              default_val: "0.7"
            - name: "max_tokens"
              label: "最大回复长度"
              desc: "控制模型输出的 Tokens 长度上限。通常 100 Tokens 约等于 150 个中文汉字。"
              type: "int"
              min: "1"
              max: "4096"
              default_val: "2048"
            - name: "top_p"
              label: "Top P"
              desc: "生成时选取累计概率达 top_p 的最小 token 集合，集合外 token 被排除，平衡多样性与合理性。"
              type: "float" #
              min: "0.001"
              max: "1.0"
              default_val: "0.7"

  2. 保存文件。

### 步骤三：启动服务

[](<https://github.com/coze-dev/coze-loop/wiki/2.-%E5%BF%AB%E9%80%9F%E5%BC%80%E5%A7%8B#步骤三启动服务>)

执行以下命令，使用 Docker Compose 快速部署 Coze Loop 开源版。
    
    
    # 启动服务，默认为开发模式
    # 在 coze-loop/目录下执行
    make compose-up

### 深度定制 Kubernetes 部署逻辑

[](<https://github.com/coze-dev/coze-loop/wiki/2.-%E5%BF%AB%E9%80%9F%E5%BC%80%E5%A7%8B#深度定制-kubernetes-部署逻辑>)

Helm Chart 部署逻辑源码位于 `https://github.com/coze-dev/coze-loop.git` 的 `release/deployment/helm-chart` 目录下，你可以可自由定制其中的代码逻辑。

  1. 在 `release/deployment/helm-chart` 目录下定制代码逻辑。
  2. 在根目录 `coze-loop/` 下执行命令`make helm-chart-deps`，更新 local chart 包。
  3. 执行命令 `make helm-up`，将定制的代码逻辑部署到 kubectl 的默认集群中进行验证。 你可以执行命令 `make helm-help`，查看包装好的所有 Helm 命令的用法。

* **Windows** ：推荐使用 Docker Desktop 安装，参考 [Docker Desktop For Windows](<https://docs.docker.com/desktop/setup/install/windows-install/>) 安装指南。  
Docker 资源配置 | 建议使用 4 核 8G 及以上。

### 通过 Minikube 部署 Coze Loop

[](<https://github.com/coze-dev/coze-loop/wiki/2.-%E5%BF%AB%E9%80%9F%E5%BC%80%E5%A7%8B#通过-minikube-部署-coze-loop>)

  1. 本地项目中执行以下命令，启动 Minikube 并开启通道。
         
         # 配置 host 
         sudo vim /etc/hosts
         # 添加以下内容
         127.0.0.1 open.coze-loop.minikube
         
         # 在helm chart包 coze-loop/ 目录下执行以下命令，启动 Minikube 集群
         make minikube-start 
         
         # 开启 Minikube 通道，使其可以通过 localhost 访问
         # 在 helm chart包 coze-loop/ 目录下执行。此操作会阻塞当前终端，直到主动关闭 tunnel
         make minikube-tunnel 

  2. 执行以下命令，部署并启动 Coze Loop。
         
         # 在 coze-loop/目录下执行
         make helm-up-exp-minikube-bundle
         # 等待服务部署完成后，查看集群pod状态
         make helm-pod
         # 查看服务启动日志，如果 app 和 nginx 均正常运行，表示部署成功
         make helm-logf-app
         make helm-logf-nginx

  3. 访问 Coze Loop。 至此，你已成功部署 Coze Loop 开源版。启动服务后，使用浏览器访问 `http://open.coze-loop.minikube`，即可体验 Coze Loop 的各项功能与服务。 其中域名 `open.coze-loop.minikube` 为默认域名，你也可以在项目根目录下修改 `values.yaml` 文件，将其改为业务相关的域名。

# 公网安全风险

[](<https://github.com/coze-dev/coze-loop/wiki/2.-%E5%BF%AB%E9%80%9F%E5%BC%80%E5%A7%8B#公网安全风险>)

如果要将 Coze Loop 部署到公网环境下，建议关注以下安全风险：

  * 建议关闭注册功能，或开启邮箱白名单，否则任意用户均可通过链接使用。
  * 建议根据业务需求（例如内网访问）为部署环境配置网络，规避 SSRF 风险。
  * 建议通过环境变量 COZE_LOOP_SESSION_HMAC_KEY 配置 session HMAC 密钥。
  * Coze Loop 服务端默认只监听 localhost，部署到公网环境下时建议仅在必要时监听 0.0.0.0，或者增加额外的安全措施，以免服务直接暴露在公网。

    make compose-up

         }

## 部署时报错端口冲突

[](<https://github.com/coze-dev/coze-loop/wiki/2.-%E5%BF%AB%E9%80%9F%E5%BC%80%E5%A7%8B#部署时报错端口冲突>)

当前版本 Docker Compose 网络整体只对外暴露 3 个端口，其余服务均为 Docker Compose 网络内部相互访问调用，并未暴露。 如果部署时报错端口冲突，你可以根据提示信息找到端口冲突的服务，手动修改 `release/deployment/docker-compose/.env` 文件，为端口冲突的服务切换其他空闲端口，然后重启对应的服务。 各个服务的端口修改方式如下：

**服务** | **默认端口** | **修改方式**  
---|---|---  
coze-loop-nginx | 对外访问 Coze Loop 网站的端口默认为 8082   
| 1\. 在 `release/deployment/docker-compose/.env` 文件中，修改配置变量 `COZE_LOOP_NGINX_PORT`，改为其他空闲端口。   
2\. 执行命令 `make compose-restart-nginx`，重启 Nginx 服务。  
coze-loop-app | Open API 端口默认为 8888   
| 1\. 在 `release/deployment/docker-compose/.env` 文件中，修改配置变量 `COZE_LOOP_APP_OPENAPI_PORT`，改为其他空闲端口。   
2\. 执行命令 `make compose-restart-app`，重启 app 服务。  
| 单步调试 Debug 端口默认为 40000 | 1\. 在 `release/deployment/docker-compose/.env` 文件中，修改配置变量 `COZE_LOOP_APP_DEBUG_PORT`，改为其他空闲端口。   
2\. 执行命令 `make compose-restart-app`，重启 app 服务。
