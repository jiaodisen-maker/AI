# 飞书 ⇄ 扣子深度结合方案

> 配合 `PLAN.md` + `SALES-BOT.md` 食用。
> 信息源：`raw/coze_cn/{guides,cozespace,tutorial}/*feishu*.md` 8 篇官方文档。

## 0. 核心结论

**飞书和扣子的结合不是"装个机器人"——是 8 层全栈渗透**。
你 800 人公司 + 已用飞书 + 企业旗舰版 → 这套**最适合你**。
其他用钉钉/企微的公司没这么深度的官方支持。

---

## 1. 8 层结合全景图

```
┌──────────────────────────────────────────────────────┐
│ Layer 8 治理层  │ 企业旗舰版工作空间集成可管控       │ ★企业旗舰版独享
├──────────────────────────────────────────────────────┤
│ Layer 7 沉淀层  │ 对话日志 → 多维表格归档            │ ★高价值
├──────────────────────────────────────────────────────┤
│ Layer 6 合规层  │ 飞书审批 = bot 操作护栏            │ 自建插件
├──────────────────────────────────────────────────────┤
│ Layer 5 触达层  │ bot 推卡片/文档/@/任务到飞书       │ ★原生支持
├──────────────────────────────────────────────────────┤
│ Layer 4 流程层  │ 日历 / 会议纪要 / 任务跟进          │ ★Agent World
├──────────────────────────────────────────────────────┤
│ Layer 3 数据层  │ 多维表格做客户/订单/任务"软数据库"  │ ★最重要
├──────────────────────────────────────────────────────┤
│ Layer 2 入口层  │ bot 发布到飞书（私聊+群聊）         │ ★必做
├──────────────────────────────────────────────────────┤
│ Layer 1 身份层  │ SAML SSO + 通讯录 → 自动识别员工    │ ★企业旗舰版独享
└──────────────────────────────────────────────────────┘
```

8 层都是文档里**官方支持的能力**。下面逐层展开。

## 2. Layer 1 · 身份层（SAML SSO + 通讯录）

### 2.1 能力（**企业旗舰版独享**）

> 来源：`guides/configure_sso_from_feishu.md`

- 飞书作为 IdP，扣子作为 SP
- 员工登飞书 → 链接直跳扣子，**不用再输扣子账号密码**
- 用员工邮箱前缀做唯一标识（`alice_123@company.com` → 扣子用户名 `alice_123`）

### 2.2 对销售助手的价值

```
销售小王在飞书私聊 bot："今天有哪些 A 类客户没跟"
                        │
                        ▼
       bot 收到消息时已经带：
         - employee_id = wang_xx
         - 部门 = 销售部·华东
         - 上级 = 张经理
         - 角色 = sales-rep
                        │
                        ▼
       bot 直接调 list_upcoming_renewals(salesperson_id=wang_xx)
       不用问"你是谁"，不用让用户输工号
```

### 2.3 配置步骤（你工程师 1 周做完）

1. 扣子编程企业管理 → SSO 设置 → 拿 SP 元数据 (ACS URL + Entity ID)
2. 飞书开放平台 → 应用管理 → 添加自建应用 → 配置 SAML SSO
3. 在飞书填扣子的 ACS URL，扣子填飞书的 SAML 元数据
4. 在扣子里**预创建企业成员**（用户名 = 飞书邮箱前缀）
5. 在飞书设置可见范围（哪些员工能用）

⚠️ **必须做**：通讯录同步（飞书 API → 扣子成员表），否则 800 人手动建账号要疯。
工程师 1 写一个**通讯录同步守护进程**：飞书 API → 扣子 OpenAPI 创建/禁用成员。

## 3. Layer 2 · 入口层（bot 发布到飞书）

### 3.1 能力（**所有版本支持**）

> 来源：`guides/publish_to_feishu.md`、`cozespace/using-coze-in-feishu.md`

- 智能体发布 → 选飞书渠道 → 授权 → 飞书机器人自动建好
- 私聊 + 群聊都能触发
- 扣子（主产品）已经做了 Agent World 深度结合，**一键开启飞书即可读消息/写文档/管多维表格/管日程/管任务**

### 3.2 对销售助手的价值

```
方式 1：私聊（最常用）
  小王 → 飞书 → @销售助手 → 直接对话
  
方式 2：群聊（销售部群）
  销售部群 → @销售助手 "@销售助手 本周到期客户"
  bot 在群里回复（其他人能看到，方便互助）

方式 3：销售助手@特定人
  bot 工作流通过自定义机器人 webhook
  "@小王 你的客户 张三 30 天后续约，建议本周联系" + 卡片
```

### 3.3 关键限制

⚠️ **同一飞书租户内才能分享智能体**——不支持跨租户共享。
你公司是单租户，没问题。

## 4. Layer 3 · 数据层（多维表格做"软数据库"，**核心**）

### 4.1 能力（**所有版本支持，但企业旗舰版可管控**）

> 来源：`guides/feishu_base_integration.md`

扣子工作流可以对**任意已授权**的飞书多维表格做：

| 操作 | 单次上限 |
|---|---|
| 创建多维表格 | - |
| 创建/删除数据表 | - |
| 增删改字段 | - |
| **新增记录（批量）** | **500 条** |
| **更新记录（批量）** | **500 条** |
| **查询记录** | **500 行** |
| 删除记录（批量）| - |
| 高级筛选 / 视图 | ✅ |

### 4.2 为什么用多维表格 ≠ 扣子数据库

| 维度 | 扣子数据库 | 飞书多维表格 |
|---|---|---|
| **业务方能直接看/编辑** | ❌ 看不到 | ✅ 飞书里直接打开 |
| 字段灵活度 | 20 字段上限 | 实际无限 |
| 视图（按阶段/按销售/按到期）| 工作流自己写 | ✅ 飞书视图原生支持 |
| 单表行数 | 10 万 | 飞书单表数百万行 |
| 业务方协作 | 不行 | ✅ 飞书协作原生 |
| 自动化触发 | 触发器内 | 飞书自带自动化（多维表格触发器）|
| **数据可见性** | bot 内部 | **业务方"打开飞书就能看"** |

### 4.3 销售助手怎么用多维表格

#### 客户档案表（核心数据）

```
表名: 销售客户档案
字段:
  - 客户ID (单行文本，主键)
  - 客户名称 (单行文本)
  - 客户公司 (单行文本)
  - 跟进销售 (人员，关联飞书通讯录)        ← 关键！
  - 阶段 (单选: lead/qualified/won/...)
  - 客户分级 (单选: A/B/C)
  - 最后跟进 (日期时间)
  - 合同到期 (日期时间)                      ← 续约触发依据
  - 跟进摘要 (多行文本)
  - 标签 (多选)
```

视图（飞书原生，**不用 bot 写**）：
- "我的 A 类客户" — 跟进销售=当前用户 + 分级=A
- "本周到期" — 合同到期 BETWEEN today AND today+7
- "30 天没跟" — 最后跟进 < today-30

bot 通过多维表格集成做：
- 销售问"我的 A 类客户" → bot 调"查询记录"+ filter
- bot 提醒续约 → 走"本周到期"视图
- 销售更新跟进 → bot 调"更新记录"

#### 订单跟进表

```
字段: 订单ID / 客户ID（关联客户档案）/ SKU / 金额 / 状态 / 日期
```

#### 销售活动日志

```
字段: 时间 / 销售 / 客户ID / 活动类型 / 摘要 / 下次跟进
```
所有 bot 跟客户的对话**自动**沉淀进这表（Layer 7 沉淀层）。

### 4.4 配置步骤

1. 飞书里建一张"销售客户档案"多维表格（建议放在销售部独立空间）
2. 扣子工作空间 → 集成管理 → 飞书多维表格 → 授权（绑定**一个飞书账号**，建议公司公账或销售运营账号）
3. 工作流里加飞书多维表格节点 → 选择刚授权的表

⚠️ **关键约束**：一个工作空间只能绑**一个飞书账号**给多维表格。
所以**销售所有客户档案放一个公账下**——不要每个销售各自存。

## 5. Layer 4 · 流程层（日历 + 会议纪要 + 任务）

### 5.1 能力（**Coze 主产品 = 扣子，已通过 Agent World 接好**）

> 来源：`cozespace/using-coze-in-feishu.md`

| 飞书功能 | bot 能干 |
|---|---|
| **日历** | 创建/查询/修改/删除日程 / 搜索日程 / 查参会人忙闲 |
| **会议** | 读会议纪要、转写文本 |
| **任务** | 创建/更新/完成任务 / 子任务 / 评论 |
| **文档** | 创建/更新/读取云文档 |

### 5.2 销售助手 = 飞书日历的智能调度员

```
销售：明天下午能不能约客户王总开个会，看看你和他的忙闲
  ↓
bot 工作流：
  1. 查飞书通讯录拿王总 user_id
  2. 调日历 API "freebusy"，查双方 14:00-18:00 忙闲
  3. 找最早的 1 小时空档
  4. 创建日程草稿（不直接发）
  5. 飞书卡片回销售："我建议明天 15:00-16:00，下面是日程草稿，确认发起？"
  6. 销售点确认 → bot 调日历"创建日程" → 邀请王总
```

### 5.3 销售助手 = 会议纪要消化器

```
[销售开飞书会议讨论 X 客户，会议自动转写]
  ↓
[飞书事件：会议结束]      ← 通过自定义机器人 webhook 监听
  ↓
[bot 工作流]
  1. 拉会议转写
  2. LLM 抽取：客户 ID / 关键决策 / 行动项 / 风险
  3. 更新多维表格"销售客户档案"的"跟进摘要"字段
  4. 创建飞书任务（行动项）@ 对应人
  5. 卡片摘要发到销售部群
```

### 5.4 销售助手 = 跟进任务追踪器

bot 提示销售时**不只发消息，直接创建飞书任务**：

```
卡片消息：A 类客户「张总」30 天没跟进 ⚠️
[创建跟进任务] [稍后再说] [标记不再跟]
        ↓
   销售点击 → bot 调飞书任务 API → 创建任务 + 设截止 + 关联客户
        ↓
   销售完成任务 → 飞书任务变更事件 → bot 回写多维表格"最后跟进"
```

## 6. Layer 5 · 触达层（主动推送）

### 6.1 三种推送方式

| 方式 | 何时用 | 能力 |
|---|---|---|
| **飞书消息插件**（自定义机器人 webhook）| 工作流主动推 | 文本/富文本/卡片 + @ |
| **bot 发布到飞书后的"主动消息"** | 智能体侧主动 | 通过飞书 OpenAPI |
| **飞书云文档** | 长内容（周报/纪要）| 文档 + 群消息链接 |

### 6.2 销售助手主动推送清单

| 触发 | 频率 | 推送内容 | 推给谁 |
|---|---|---|---|
| 续约提醒 | 周一 09:00 | 卡片：30 天内到期客户清单 | 每个销售私聊 |
| 异常告警 | 实时 | A 类客户超 14 天没跟 | 销售 + @主管 |
| 周报草稿 | 周五 17:00 | 飞书云文档（草稿）| 销售个人 |
| 月度复盘 | 每月 1 日 | 多维表格视图 + 文档 | 主管 + 销售部群 |
| 关键事件 | 实时 | "你的客户在抖音留言" | 销售个人 |

### 6.3 卡片设计示例

```yaml
# 续约提醒卡片
header:
  title: "🔔 本周到期客户跟进 (3 个)"
  template: "yellow"
elements:
  - tag: div
    text:
      content: |
        **客户A**（A 类，2026-05-12 到期）
        最后跟进：2026-04-15（19 天前）
        建议话术：[查看]
    extra:
      tag: button
      text: "立即跟进"
      type: primary
      value: { action: "create_task", customer_id: "C123" }
  - tag: hr
  - tag: div
    text:
      content: "**客户B** (B 类, ...)"
  ...
```

### 6.4 配置步骤

1. 飞书 → 群组（或私聊） → 添加自定义机器人 → 拿 webhook URL
2. 扣子 → 集成管理 → 飞书消息 → 填 webhook URL
3. 工作流加飞书消息节点

⚠️ **企业旗舰版**：在工作空间集成管控里**先开启**飞书消息集成（默认关闭）。

## 7. Layer 6 · 合规层（飞书审批做护栏）

### 7.1 思路

保健品行业敏感操作 → **bot 不直接做，先走飞书审批**：

| 敏感操作 | 走审批 |
|---|---|
| 客户报价 > 阈值 | 销售总监审批 |
| 给客户发对外营销邮件 | 法务审批 |
| 客户档案大批量导出 | DPO 审批 |
| 给客户做"产品推荐" | 自动合规扫描 + 抽查审批 |

### 7.2 实现

飞书没有原生 Coze 审批集成，**自建插件**：
- 工程师 2 写一个"飞书审批"OpenAPI 插件
- 用飞书审批 OpenAPI（`open-apis/approval/...`）
- 工作流：bot 准备好操作 → 调审批插件 → 等审批结果 → 执行 OR 拒绝

### 7.3 销售助手示例

```
销售："给王总发个续约报价 8 折"
  ↓
bot 检测：报价折扣 > 7 折 → 走审批
  ↓
bot 调飞书审批 API 发起："销售小王申请给客户 X 报 8 折"
  ↓
销售总监收到飞书审批 → 通过/拒绝
  ↓
bot 收到审批结果 webhook
  ↓
PASS → 生成话术 + 客户档案记录这次报价  
REJECT → 告诉销售 "未通过，需调整为 9 折以上"
```

## 8. Layer 7 · 沉淀层（数据回流）

### 8.1 思路

**bot 跟人的所有交互，都该沉淀回多维表格**——成为下一轮训练/分析素材。

### 8.2 自动沉淀什么

| 数据 | 沉淀到哪 | 用途 |
|---|---|---|
| 销售跟 bot 的对话 | "销售活动日志"多维表格 | 周报、效率分析 |
| bot 给销售的话术建议 | "话术库"多维表格 | 优秀话术沉淀，扩黄金题集 |
| 客户问答（通过销售）| 客户档案的"跟进摘要" | 完整客户视角 |
| 失败/拒绝/转人工 | "失败模式"多维表格 | Coze Loop 黄金题来源 |
| 销售反馈（👍 / 👎）| "反馈"多维表格 | 改进 prompt |

### 8.3 销售部群聊监听（高级玩法）

bot 加到销售部群里 → 监听消息 → 自动从对话里抽业务洞察 → 进多维表格：

```
群聊："最近 X 客户老是说我们价格太贵"
  ↓
bot LLM 分析：客户 X、议题=价格、情感=负面
  ↓
更新客户档案"风险标签": +价格敏感
  ↓
推送给该客户的销售："你的客户 X 在群里被讨论价格压力，建议主动沟通"
```

## 9. Layer 8 · 治理层（**企业旗舰版独享**）

### 9.1 工作空间外部集成可管控

> 来源：`guides/feishu_message_integration.md`、`guides/internal_integrations.md`

企业旗舰版可以**按工作空间设置外部集成的可用性**：

```
组织
├── 销售空间
│   开放：飞书消息、飞书多维表格、飞书日历、CRM 插件
│   禁用：邮件、抖音、微信外部通知（防销售直接对外发邮件）
├── 客服空间
│   开放：飞书消息、CRM 插件
│   禁用：邮件、多维表格写权限
├── HR 空间
│   开放：飞书消息、邮件
│   禁用：CRM、销售系统、多维表格
└── 法务空间
    开放：所有阅读权限，禁用所有写
```

⚠️ **默认关闭**——管理员必须手动开。这是合规的天然屏障。

### 9.2 推荐治理结构

```
扣子组织
├── 总管空间（你 + 工程师 1，治理用）
├── 销售空间（销售部 + 工程师 4 + 6）
├── 客服空间（客服 + 工程师 5）
├── HR 空间（HR + 工程师 5）
├── 市场空间（市场 + 工程师 5）
├── 培训空间（培训 + 工程师 5）
└── 沙箱空间（开发实验，不能用任何外部集成）
```

每个空间独立计费、独立成员、独立外部集成、独立 KB。

## 11. 阶段性落地（4 周冲刺细化版）

### Week 1 · 身份 + 入口 + 数据底盘

- [ ] **SAML SSO 配通**（工程师 1，1d）
- [ ] **通讯录同步守护进程**（工程师 1，2d）
- [ ] **飞书多维表格"客户档案"建好**（你 + 销售运营，0.5d）

### Week 2 · 流程 + 触达

## 12. 哪些是企业旗舰版独享 vs 所有版本都有

| 能力 | 个人版 | 企业标准版 | 企业旗舰版 |
|---|---|---|---|
| 发布到飞书 | ✅ | ✅ | ✅ |
| 飞书消息插件（webhook 推送）| ✅ | ✅ | ✅ |
| 飞书多维表格集成 | ✅ | ✅ | ✅ |
| 飞书日历 / 任务 / 文档 / 会议（Agent World）| ✅（扣子主产品）| ✅ | ✅ |
| Email 集成 | ✅ | ✅ | ✅ |
| **SAML SSO** | ❌ | ❌ | **✅** |
| **工作空间外部集成可管控** | ❌ | ❌ | **✅** |
| **VPC 私有网络** | ❌ | ❌ | **✅** |
| 通讯录同步（自建插件实现）| 任意版本，自己实现 | | |

**对你的结论**：800 人公司必须企业旗舰版。否则没 SSO 没集成管控，800 人体验和合规都过不去。

## 13. 风险 + 对策

| 风险 | 严重度 | 对策 |
|---|---|---|
| 多维表格授权账号离职 | 🔴 高 | 用**公账**（如 `bot-ops@company.com`），不是个人账号 |
| 飞书 API 限流（多维表格 500 行/次）| 🟡 中 | 工作流分页查询；> 500 客户的销售用 SQL DB 兜底 |
| SSO 配错员工不能登 | 🔴 高 | 灰度先 5 个销售试 1 周，再全员推 |
| 销售在群里 @bot 被无关人员滥用 | 🟡 中 | bot prompt 加白名单：只回销售部成员 |
| bot 推送过多 = 骚扰 | 🟡 中 | 每人每天推送上限 5 条；销售可关订阅 |
| 飞书租户搬家 / 改名 | 🟢 低 | 重新授权即可，数据在多维表格保留 |
| 多维表格被业务方误删 | 🟡 中 | 每天导出快照（飞书 API 拉数据进 SQL 备份）|
| 跨租户分享需求 | 🟢 低 | 不支持，告诉外部合作方走 API 而非 bot |
